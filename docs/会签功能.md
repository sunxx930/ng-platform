# 审批会签（2026-10-30）

> 一句话：一个审批请求指定多名会签人，**全部签署同意才通过；任一驳回即退回**（或签规则下任一同意即通过）。

## 1. 适用场景

- 项目负责人 + 部门负责人 + 合伙人共同审签流程变更、对外交付、资金动作等 L3/L4 事项。
- 会签人不必是项目 owner：被点名后可在「我的会签」面板（跨项目）看到并签署；通知也会送到本人。

## 2. 规则

| 参数 | 值 | 含义 |
|---|---|---|
| `rule` | `all`（默认） | 会签：全部同意才通过；任一驳回立即退回 |
| `rule` | `any` | 或签：任一同意即通过；全部驳回才退回 |

- 每人只能签一次自己的名字，**不能代签**；已签署不能改签。
- 驳回必须填写 `opinion`。
- 有会签人的审批，禁止走 `POST /approvals/{id}/decision`（防止 L3 一步代签）。
- 未设置会签人的审批保持原单人审批语义，完全兼容旧流程。

## 3. API

### 发起会签（L3）

```http
POST /tasks/{tid}/approvals?scope=flow_change&signers=张三,李四&rule=all
```

- `signers`：逗号分隔（兼容中文逗号/顿号），去重保序；最多 20 人。
- 会签人必须是已注册账号或服务器静态 token 身份（`admin` / `agent`）。
- 任务若在 `in_review`，发起后自动推进 `pending_approval`。

### 给已有审批补设会签人（L3）

```http
POST /approvals/{aid}/signers?signers=张三,李四&rule=all
```

- 仅允许在**尚无人签署、未出结论**时调整；已有签署则 400。

### 签署（会签人本人）

```http
POST /approvals/{aid}/sign?result=approve
POST /approvals/{aid}/sign?result=reject&opinion=材料不完整
```

- 返回 `status`：`pending` / `approve` / `reject`，以及 `progress`。
- 重复签署同一结果幂等返回；改签 400。
- 终态后其他会签人再签 400。

### 我的会签（跨项目）

```http
GET /approvals/pending
```

返回当前用户被指定为会签人、尚未出结论的审批，包括项目/任务标题、会签人状态、`my_signature`、进度。

### 会签人选人名单（L3）

```http
GET /users
```

只返回用户名/级别，不含密码哈希。

## 4. 事件模型（append-only）

| 事件 | 写入方 | 关键 payload |
|---|---|---|
| `approval.requested` | system | `approval_id, scope, signers, rule, initiator` |
| `approval.signers_set` | L3 用户 | `approval_id, signers, rule` |
| `approval.signed` | 会签人 | `approval_id, signer, result, opinion` |
| `approval.decided` | system | `approval_id, result, scope, countersign=true` |

- 终态由系统补 `approval.decided`（幂等键 `approval:dec:{aid}`），之后复用原有任务状态联动（通过→`completed`，驳回→`in_progress`）。
- 所有签署均留痕在审计流，前端审计记录显示「会签签署」「会签通过/驳回」。

## 5. 前端

- 顶栏下方的「我的会签」面板：显示跨项目待签审批、会签人状态（✅/❌/⏳）、`n/m 已签`，可直接签署/驳回。
- 任务看板：待复核任务出现「🤝 发起会签」（L3），可选会签人（`/users` 提供候选）与规则。
- 待办中心：待审批行显示会签进度；会签人本人出现「签署同意 / 驳回」；L3 可对未签字的普通审批点「🤝 设为会签」。

## 6. 测试

```bash
.venv/bin/python -m pytest tests/test_countersign.py -q
```

覆盖：全部同意通过、驳回否决、非会签人 403、重复签署幂等、既有审批补设会签人、旧单人审批兼容、或签规则、跨项目待签列表与隔离、会签人通知。

> DB 模式（`DATABASE_URL`）无需迁移：事件表 `event_type` 为 TEXT，投影器对未知事件忽略；用户名单走 `users` 表。
