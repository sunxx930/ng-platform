# NG-AI-Platform 升级模式说明（类 openclaw）

目标：发布/升级像 openclaw 一样**有版本号、有清晰"升级内容"清单、可追溯**，用户和运维一眼知道"这版改了什么"。

## 一、版本与发布物
- 版本号三档：**主.次.补丁**（如 v1.1.2）；每个版本在 `CHANGELOG.md` 有对应小节。
- 发布物（每版）：
  - macOS 公证安装包 `dist/NG-AI-Platform.dmg`（`FORCE_REPACK=1 bash scripts/sign_mac.sh` 出）
  - Windows 单文件 `dist\NG-AI-Platform.exe`（Windows 机跑 `build_windows.bat`）
  - 官网下载页更新（挂 DMG/exe + 本版"升级内容"）
- 用户侧"升级"= **下载新版 → 覆盖安装**，数据保留（存 `~/.ng-platform/`，不随包删）。

## 二、CHANGELOG 怎么写（每次发版必填）
新版本在**最上面**加一节：
```
## vX.Y.Z（日期）— 一句话主题
**新增** / **修复** / **安全** / **其他**
- 每一条一句、用户看得懂（口语化）；安全/修复项标明影响
```
写完 CHANGELOG 才算发版；`git tag vX.Y.Z` 打标签（可选，便于回溯）。

## 三、"升级内容"展示到哪
- 程序内：顶部标题/`/health` 显示版本号（后续可加"更新内容"接口，非必须）
- 官网下载区：每版列 changelog 条目（本文件即源）
- 给测试/验收：发版邮件/群聊直接贴当节"升级内容"，对齐复验范围

## 四、流程锚点（配合 docs/升级与重启步骤.md）
1. 改动代码 → pytest 全绿 → 前端改动则 `npm build` 并 `git add -f frontend/dist`
2. 写/改 CHANGELOG 该版本条目
3. 提交+推送 → CI e2e 绿
4. 出包（mac sign_mac.sh / win build_windows.bat）→ 验签
5. 官网下载页更新 + 贴升级内容

## 五、运维侧（服务器/网关）
- openclaw 网关、自身服务各有独立版本与日志（见 升级与重启步骤.md §5）；ng-platform 自身的"升级模式"以上述为唯一口径。

## 六、代码补丁模式（v1.3.0 起，日常更新的默认路径）

**用户 2026-09-27 定：以后版本更新都走补丁，不再覆盖安装。**
约束原话："要考虑到客户已经开始项目，覆盖会破坏进程。"

### 形态
把程序拆成「外壳 + 载荷」：

```
安装包（很少变）= 启动器(ng_boot) + Python 运行时 + 原生依赖
补丁（几百 KB）= app/ 业务代码 + frontend/dist 界面 + payload.json 清单
```

启动时 `ng_boot` 把 `NG_HOME/code/versions/<版本>/` 插到 `sys.path` 最前，
**先于 `_MEIPASS` 被命中**，从而覆盖打包进 PYZ 的 `app.*`（PyInstaller 6.22 的 PYZ
是 path-entry finder，不是 meta-path finder；此结论已用真实构建实测）。

### 为什么"下次启动才生效"
桌面版是**单进程**（worker 与 uvicorn 同进程两个线程）。运行中换代码必然打断正在跑的
agent；而启动那一刻天然没有在跑的活。所以：**补丁只下载暂存，切换交给下次启动** ——
这是结构性保证，不依赖任何"忙检测"。界面提示"更新已就绪，下次启动生效"。

### 安全
- 补丁用**发行方 Ed25519 私钥**签名（与授权串同源，`~/.secrets/ng-license/`）。
- 签的是**规范化描述符**（`ng_crypto.code_descriptor`）：绑定 version / min_shell /
  payload_api / seq / sha256 / size —— 改任一字段签名即失效，杜绝"旧包配新版本号"的降级与回放。
- 客户端校验顺序 fail-closed：验签 → 兼容性 → 下载 → sha256 → 防重放(seq 递增) →
  解压(穿越防护) → 逐文件 sha256 → 原子写 pending。
- 私钥**绝不进 CI**，沿用本地签名（同授权/公证流程）。

### 回滚
- `import app.main` 就炸 → **同一次启动内**当场回退上一版/打包版，坏版本进 `quarantine/`。
- 启动后异常退出（未确认）→ **下次启动**检测到未确认，回退。
- 打包版永远是最终兜底 —— 坏补丁不可能让 App 打不开。

### 发布步骤
```bash
# 1) 改代码、跑测试，把 app/version.py 的 VERSION 提到新版本
# 2) 打补丁
python3 scripts/build_code_patch.py --version 1.3.1 --out dist
# 3) 签名（本机，需要发行方私钥）
python3 scripts/issue_code_patch.py --version 1.3.1 --zip dist/code-1.3.1.zip \
    --url https://github.com/sunxx930/ng-platform/releases/download/v1.3.1/code-1.3.1.zip \
    --out dist/code-1.3.1.json
# 4) 把 zip 挂 GitHub Release；把 code 段并进 update.json 并推送
python3 scripts/gen_update_manifest.py --code dist/code-1.3.1.json
#    （gen_update_manifest 现在会保留 knowledge / knowledge_regs / code 各内容域）
```
客户端每天自动拉一次 `/update/apply` 即会暂存新补丁，无需用户操作。

### 什么情况仍要重装
只有改动**原生依赖/运行时**（新增 .so/.pyd、升 Python、改打包钩子）时才需要出新安装包。
届时把载荷的 `min_shell` 提到该安装包版本，老外壳会**明确拒绝**并提示"需要新版安装包"，
绝不半途应用。

> 一次性迁移：1.2.x 的安装包里没有 `ng_boot`，无法加载载荷 —— 存量用户需重装一次
> **v1.3.0** 才能进入补丁模式。这是最后一次重装。
