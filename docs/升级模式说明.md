# NG-AI-Platform 升级模式说明（类 openclaw）

目标：发布/升级像 openclaw 一样**有版本号、有清晰"升级内容"清单、可追溯**，用户和运维一眼知道"这版改了什么"。

## 一、版本与发布物
- 版本号三档：**主.次.补丁**（如 v1.1.2）；每个版本在 `CHANGELOG.md` 有对应小节。
- 发布物（每版）：
  - macOS 公证安装包 `dist/NG-AI-Platform.dmg`（`FORCE_REPACK=1 bash scripts/sign_mac.sh` 出）
  - Windows 单文件 `dist\NG-AI-Platform.exe`（Windows 机跑 `build_windows.bat`）
  - 官网下载页更新（挂 DMG/exe + 本版"升级内容"）
- 用户侧"升级"= **下载新版 → 覆盖安装**，数据保留（存 `~/.ng-platform/`，不随包删）。

## 二、CHANGELOG 怎么写（每次发版必填）
新版本在**最上面**加一节：
```
## vX.Y.Z（日期）— 一句话主题
**新增** / **修复** / **安全** / **其他**
- 每一条一句、用户看得懂（口语化）；安全/修复项标明影响
```
写完 CHANGELOG 才算发版；`git tag vX.Y.Z` 打标签（可选，便于回溯）。

## 三、"升级内容"展示到哪
- 程序内：顶部标题/`/health` 显示版本号（后续可加"更新内容"接口，非必须）
- 官网下载区：每版列 changelog 条目（本文件即源）
- 给测试/验收：发版邮件/群聊直接贴当节"升级内容"，对齐复验范围

## 四、流程锚点（配合 docs/升级与重启步骤.md）
1. 改动代码 → pytest 全绿 → 前端改动则 `npm build` 并 `git add -f frontend/dist`
2. 写/改 CHANGELOG 该版本条目
3. 提交+推送 → CI e2e 绿
4. 出包（mac sign_mac.sh / win build_windows.bat）→ 验签
5. 官网下载页更新 + 贴升级内容

## 五、运维侧（服务器/网关）
- openclaw 网关、自身服务各有独立版本与日志（见 升级与重启步骤.md §5）；ng-platform 自身的"升级模式"以上述为唯一口径。
